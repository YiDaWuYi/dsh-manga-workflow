# DSH 接管说明 · 漫画汉化工作流

> 这个文件由「漫画工作台」插件在你的工作区里自动生成。
> **新建 DSH 对话后,先读这一份**,就知道用户的工作、目录、流程,以及需要 DSH 接管时该做什么。
> 文件会随插件更新自动刷新,不需要手工改。

---

## 一、用户要做什么

用户在做**漫画汉化**:把日文(或韩文)漫画做成中文版。

- 输入端:一个漫画文件夹(一堆 `00000001.webp` 之类的图片);
- 输出端:同样数量的中文成品图(PNG),放在工作区的「已完成」目录里;
- 中间数据:每个页面上标出的「框」(regions)、每框的日文原文(ocr_text)、中文译文(trans)。

判断一本书缺什么,可以用 `manga_status` 工具,看「未翻译页 / 未翻译框」。

---

## 二、工作区的目录结构

| 路径 | 说明 | 能不能写 |
| --- | --- | --- |
| `<工作区>\工作区文件\<书名>\` | 用户放原图的地方(**源目录**) | **只读,绝对不要写** |
| `<工作区>\projects\<书名>\` | 项目库:框、原文、译文、配置、中间产物 | 可写(插件管理) |
| `<工作区>\已完成\<书名>\` | 成品输出(嵌字后的 PNG + README) | 可写 |
| `<工作区>\out\` | 临时测试产物 | 可写,可清 |
| `<工作区>\dist\` | 插件安装包下载位置 | 一般不需要动 |

项目库里的关键文件:

| 文件 | 内容 |
| --- | --- |
| `regions.json` | `{ 页键: [ {kind, cover, gpu, vertical, size, points:[{x,y}], auto, style, font} ] }` |
| `trans.json` | `{ 页键: ["中文译文", ...] }`,与 regions 的框**按数组下标一一对应** |
| `ocr_text.json` | `{ 页键: ["日文原文", ...] }` |
| `config.json` | 这本书的配置(是否用 LaMa、语言等) |
| `meta.json` | 项目元信息(来源目录、创建时间) |
| `out_lama\` | 嵌字中间产物 |
| `out\embed_report.md` | 最近一次嵌字的报告(问题/警告列表) |

**页键就是图片文件名去扩展名**,例如 `00000015`。

> 重要:python 脚本读数据目录由环境变量 `MANGA_DATA_DIR` 控制。
> 直接在命令行跑脚本时必须传它,否则会写到源目录(违反“源目录只读”)。

## 三、标准工作流(用户的主流程)

1. **标注**:在网页工作台或桌面工具里画框,选类型(正文 / 无框正文·拟声词 / 标题)、原文处理(译文直盖 / 抹除 / 色块覆盖)、方向。
   - 自动标框的结果(`auto: true`)默认**不参与嵌字**,必须人工确认后再用。
2. **OCR**:本地识别日文原文,写入 `ocr_text.json`。个别框识别失败时可开「OCR 兜底」(付费视觉引擎)。
3. **翻译**:免费引擎 / AI 接口 / DSH 模型,写入 `trans.json`。
4. **校对**:自动检查(数组对齐、缺译文、无效译文、艺术字、同源拟声统一),出报告;人工再改有问题的框。
5. **嵌字**:`embed_regions.py`,按框把原日文抹掉/盖掉,叠加中文;开 GPU 时走 LaMa。
6. **成品**:嵌字完成后,PNG 输出到 `已完成\<书名>\`,`embed_report.md` 记录问题。
7. 用户在网页端看预览(表单 + 逐页翻),不满意就回来改框/改译文,再跑。

**拟声词规则**:拟声词(`kind: "plain"`)固定「译文直盖」——不做抹除、不做色块覆盖、不清原字,只把中文叠上去。
**叠字不清**:直盖就是“直接盖”,底下原日文可能透出来,这是用户认可的默认行为。

## 四、什么时候需要 DSH(对话里的模型)接管

### A. 用户在对话里说「执行嵌字」「把这本书嵌了」等

1. 用 `manga_status` 看这本书的状态(路径问用户,或在 `工作区文件` 下找);
2. 数据在 `projects\<书名>\`(老书首次调用工具的会自动导入);
3. 直接调用工具:`manga_ocr` → `manga_dsh_translate`(没译文的)→ `manga_embed`;
4. 读 `projects\<书名>\out\embed_report.md`,把「问题数/警告数/典型问题」用中文简短汇报;
5. 成品会在 `已完成\<书名>\`,告诉用户去那里看。

### B. 用户点了网页端「交给对话」

工作区会出现一个 `pending_embed_request.json`(或同类请求文件),里面带着书的路径和需求。
读它 → 按请求执行(通常就是 A 的第 3~4 步)→ 执行完用 `manga_report` 取报告(取完会把文件改名 `.done`)。

### C. 用户让你「更正错误译文 / 某几页翻错了」

1. 先定位:哪一页、哪几个框(用户说页号最好;没有就用工具/报告找可疑项);
2. 改 `projects\<书名>\trans.json`(改前先备份 `trans.json.bak_原因`);
3. 只改用户点名的框,**不要顺手重译整本**;
4. 改完可以只重嵌那几页(嵌字脚本支持单页,或跑整本,讲清楚代价)。

### D. 用户在网页端点「DSH汉化模式」(整本视觉识别 + DSH 翻译 + 参与嵌字 + 校对)

这步由插件后台自己跑(会先弹花费预估),**不需要模型在对话里做**;
只有在它失败、或用户转回来让你接手时,才按 A 处理。

## 五、可用工具(优先用工具,不要手搓命令)

| 工具 | 作用 |
| --- | --- |
| `manga_status` | 看一本书:标了几页、多少框、多少已翻译、多少整页没译 |
| `manga_ocr` | 本地 OCR 全部框,写 `ocr_text.json` |
| `manga_dsh_translate` | 用 DSH 模型翻译(不要 API Key),可只翻某页 |
| `manga_embed` | 嵌字出图(可 `lama: true` 用 GPU 去字,`preview: true` 只叠字不抹原字) |
| `manga_report` | 取网页端排队过来的嵌字报告 |
| `manga_bench` | 自动标框的召回率/精确率基准(需要 GPU) |

需要更细的控制时,可以直接跑 `scripts\` 下的脚本(`ocr_regions.py`、`ocr_fallback.py`、`translate.py`、`proofread.py`、`preflight.py`、`embed_regions.py`、`embed_lama.py`),记得带 `MANGA_DATA_DIR`。

## 六、硬规则(用户明确要求过)

1. **源目录只读**:`工作区文件\<书名>\` 里的图和数据都不要改动。所有写入进 `projects\` 或 `已完成\`。
2. **改用户数据前先备份**:`trans.json.bak_<原因>`、`regions.json.bak_<原因>`,并在回复里说明回滚路径。
3. **发布/版本由用户拍板**:改插件版本、打包、push、发 Release 都要用户明确同意。
4. **测试分工**:实机/GUI 操作由用户做;你能做的是代码级验证(脚本、副本、接口、测量)。
5. **不写到桌面**:临时产物放工作区 `out\`,成品放 `已完成\`。
6. **汇报用中文、先结论**;花费敏感的操作(视觉识别/整本 DSH 汉化)先给预估。
7. 不要假设用户看得懂命令:给「点哪里」的步骤,而不是让他敲 shell。

## 七、常见坑

- **`auto` 标记**:自动标的框默认不参与嵌字;数据里残留过期 `auto: true` 会导致「有译文却没嵌上」,体检/预检脚本会自动清理,发现时要提。
- **数组对齐**:`regions` / `trans` / `ocr_text` 三份必须等长、按同一下标对应;删框或加框后要对齐,否则整页错位。
- **拟声词**:别给它设「色块覆盖」(会挡画);固定直盖。
- **LaMa(GPU 去字)**:效果最好但慢,且要求装了 torch 与模型;缺依赖时会回退,注意报告里的提示。
- **免费翻译引擎**:质量差(音译、标点乱),只适合应急;质量优先就用 AI/DSH。
- **DSH 翻译**:走 DSH 额度不额外计费;视觉识别/单页识图是付费外部引擎,按框计费。
- **图片格式**:源是 webp 时成品是 png(尺寸保持一致),不要混。

## 八、向用户汇报的格式(建议)

```
已完成:<书名> · <N> 页
- 框/<译文>:<已译框数> / <总框数>
- 嵌字:问题 <数>、警告 <数>(典型:<一两句>)
- 成品:E:\...\已完成\<书名>\
- 需要你定: <比如某页拟声词要不要换译法>
```
